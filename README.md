# zixcel-aws

An independent boundary for AWS integrations to obtain SigV4 signatures by presenting `secret://aws/...` references, principals and purposes to a Credential Authority without retaining credentials. It provides a common AWS4-HMAC-SHA256 contract for HTTP method, host, path, query, payload digest, region and service rather than a Bedrock-specific crate.

The public wire surface is fixed to these two contracts:

- `zixcel://aws/sign-request/v1`
- `zixcel://aws/sign-response/v1`

Requests cannot represent access keys, secret access keys, session tokens, raw bodies or authentication headers. Actual credentials enter `AwsCredentialMaterial` only inside an authenticated `CredentialUsePort` implementation; they support neither Debug, Serialize nor Clone and zeroize on drop.

## Usage boundary

`prepare` and `canonical_preview` are entirely offline in observe, propose and execute modes. Only `execute` calls `CredentialUsePort`, after validating the trusted clock and a maximum five-minute expiry. Credential audience (for example `aws`) and destination host are separate values bound into the request digest. Callers provide credential-custody integration through `CredentialUsePort` and own network transport.

```rust
use zixcel_aws::{parse_sign_request, prepare};

let request = parse_sign_request(include_bytes!(concat!(
    env!("CARGO_MANIFEST_DIR"),
    "/examples/sign-request.json"
)))?;
let plan = prepare(&request)?;
assert!(plan.steps.iter().all(|step| !step.external_network_required));
# Ok::<(), zixcel_aws::AwsError>(())
```

Credential references use the following reversible form without shortened aliases. Purpose and audience must equal the request's explicit scope.

```text
secret://aws/{tenant}/zixcel-aws/{purpose}/{audience}/{credential-id}
```

At execution, an authenticated owner-local Crowsi adapter implements `CredentialUsePort`. It atomically rejects request-ID reuse and matches subject, device, workload, grant, audience, purpose and host before calling `sign_with_material`.

## Bounded CLI and composition gate

The CLI forwards one stdin JSON request to an owner-local Coordinator and emits one validated stdout response. No configuration passes secret values through arguments, environment variables or stdin.

```bash
zixcel-aws sign < sign-request.json > sign-response.json
```

The socket is selected by `ZIXCEL_AWS_COORDINATOR_SOCKET`, defaulting to `$XDG_RUNTIME_DIR/zixcel-aws/coordinator.sock`. This variable holds only a socket path, not a secret. The CLI verifies an absolute non-symlink owner-owned socket, parent mode 0700, socket mode 0600, Unix peer UID, five-second timeout and 64 KiB response limit.

This repository neither implements nor starts the Coordinator daemon. Production composition must implement Crowsi's `CredentialOperationExecutor`, map public getters to `CrowsiOperationContextV1`, and pass `execute_operation` results to `ExecutorOutput::derived`. The outer action is `use-credential`; inner operation, algorithm and delivery are `sign`, `aws4-hmac-sha256` and `ipc-response`.

Credential registration accepts only versioned binary bundles generated by `credential_bundle`. Credential structs do not implement Serialize; runtime-borrowed bytes are decoded only during the operation and zeroized.

## SigV4 determinism

Input paths and queries are unencoded UTF-8; percent-encode non-RFC-3986-unreserved characters using uppercase hex. Reject ambiguous `//`, `.` and `..` path segments, signed query parameters and authentication headers fail-closed. Sort query pairs after encoding, lowercase header names and collapse repeated whitespace to one character.

`tests/canonical_vectors.rs` and `tests/signing.rs` check the official AWS SigV4 2015-08-30 `get-vanilla`, query ordering and header trimming vectors. Bedrock Mantle endpoint/service mapping is isolated in `adapters::bedrock` and examples. `tests/fixtures/hatter-sign-*.json` defines the Hatter byte-level contract; `tests/crowsi_adapter.rs` pins operation/resource digests, identity binding and effective expiry. `tests/cli_coordinator.rs` obtains signatures through an owner-local socket without sending secret values to the CLI.
